# StoryForge

Офлайн-редактор сценария для игр: ветвящиеся диалоги на графе, персонажи, локации,
переменные, валидация, экспорт в **Godot 4** (плюс Ren'Py / Markdown / JSON),
**озвучка реплик прямо в редакторе** (синтез голоса персонажа в WAV) и
AI-ассистент, который правит проект инструментами через OpenAI-совместимый API.

Electron-приложение **без сборщиков**: только `main.js`, `preload.js` и рендерер на
ES-модулях. Интерфейс доступен на русском и английском. Редактор работает офлайн и поддерживает тёмную и светлую темы.

---

## Рабочее место сценариста

Вверху находятся вкладки и история переходов. На левой ленте открываются схема, обзор связей, таблица и быстрый переход. Кнопки по краям строки вкладок сворачивают проводник и инспектор. Меню файла находится внизу проводника рядом с названием проекта.

Создайте персонажа и реплику, назначьте ей этого персонажа. Во вкладке **Таблица** нажмите **Фильтр** и введите `type:line`. Выберите реплику из результатов и откройте её в инспекторе.

Сохраните именованный вид таблицы, чтобы использовать его при следующем открытии проекта. Сочетание **Ctrl+K** ищет узлы, персонажей, главы, локации и переменные. **Enter** открывает результат, **Ctrl+Enter** открывает его в новой вкладке. Входящие переходы и места использования доступны из текстовой вкладки. Команды обзора, проигрывания и заметки за сегодня доступны на левой ленте. Двойной щелчок по свободному месту на схеме создаёт узел выбранного типа в точке щелчка.

## Установка и запуск

```powershell
cd storyforge
npm.cmd install                # в PowerShell: именно npm.cmd (Execution Policy)
npm.cmd start                  # обычный запуск
npm.cmd run start:safe         # если в вашем окружении падает Chromium (см. ниже)
```

`npm.cmd start` запускает `electron . --user-data-dir=.userdata`: профиль приложения
хранится рядом с проектом (портативный режим) — так надёжнее, чем системный
`%APPDATA%\StoryForge`.

**Если окно не появляется.** В ограниченных окружениях (контейнеры, RDP-сессии,
жёсткие политики Windows) Chromium падает ещё до старта окна с кодами
`2147483651` (0x80000003) или `4294930435`. Тогда:

```powershell
npm.cmd run start:safe         # electron . --no-sandbox --user-data-dir=.userdata
```

Дополнительно помогает явный профиль через переменную окружения:

```powershell
$env:SF_USERDATA="C:\путь\к\профилю"; npm.cmd start
```

Ключ `--user-data-dir=<путь>` тоже учитывается приложением (он же задаёт каталог
блокировки единственного экземпляра) — удобно держать отдельный профиль для
проверок, не закрывая рабочее окно.

Диагностика пишется в `.logs/main.log` (там же `render-process-gone`,
`preload-error` и сообщения консоли рендерера уровня warning/error).

## Что умеет

**Модель проекта `.sfproj`** — обычный JSON: `meta`, `startNodeId`, `characters`,
`locations`, `variables`, `chapters`, `nodes`. Узлы семи типов: `line` (реплика),
`choice` (выбор), `condition` (ветвление), `jump` (переход), `scene` (сцена),
`end` (концовка), `note` (заметка, в экспорт не попадает). Условия — строка вида
`trust_mark >= 3 && found_key`, эффекты — `{varId, op, value}`.

**Граф** — SVG-карточки 220×90, панорамирование, зум 0.25–2.5 (колесо с якорем под
курсором), перетаскивание узлов с записью позиций в проект, рёбра с подписями
вариантов и условий, контекстное меню (создать, дублировать, сделать стартовым,
удалить с перенаправлением), автораскладка по уровням графа, фильтры по главе,
тексту и заметкам. 512 узлов: отрисовка ~32 мс, валидация ~4 мс.

**Инспектор** — поля под каждый тип узла (спикер, эмоция, локация, текст со счётчиком
слов, варианты с целями/условиями/подсказками/эффектами, ветви условий, эффекты,
связи, теги, заметки, цвет), карточки персонажей/локаций/переменных/глав.

**Изображения узлов** — к узлу можно прикрепить фото: «+ фото» в инспекторе, пункт
«Изображения…» в контекстном меню графа, перетаскивание файла прямо на карточку или
`Ctrl+V` из буфера обмена. Первое изображение становится превью и рисуется на
карточке графа (полоса 200×58, узел становится выше на 74 px, рёбра учитывают новую
высоту); в инспекторе — плитки с именем и размером, переключение превью и удаление
(файл уходит из библиотеки, если больше нигде не используется), клик открывает
просмотр целиком. Файлы лежат внутри `.sfproj` как data-URL, поэтому проект остаётся
одним самодостаточным файлом; при импорте картинка сжимается в WebP до 1400 px по
длинной стороне. В экспорт Godot узел отдаёт `images: [{name, w, h}]` и `preview`,
в Markdown — строку «Изображения:».

**Левая панель** — Сценарий, Поиск, Закладки и дополнительные разделы: Персонажи, Локации, Переменные и Статистика. Поиск поддерживает фильтры по полям, **regex** и подсветку.

**Валидация** — 18 кодов проблем по 13 классам: нет стартового узла, битые ссылки,
пустой текст, недостижимые узлы, тупики, пустые/дублирующиеся варианты, отсутствие
спикера или локации, неиспользуемые персонажи/локации/переменные, битые эффекты и
условия, дубли переменных, цикл без выхода, узлы без главы.

**Экспорт** — Godot 4 (главный формат): `dialogue.json` + готовый
`dialogue_runner.gd` (`class_name DialogueRunner`, сигналы `line_shown`,
`choices_shown`, `scene_changed`, `finished`, условия через `Expression`, эффекты,
`MAX_AUTO_STEPS`) + `README.md`; плюс Ren'Py, Markdown и JSON. Битые ссылки
помечаются в каждом формате, а не молча теряются.

**AI-ассистент** — пресеты OpenAI / DeepSeek / OpenRouter / Ollama / Custom,
SSE-стриминг через main-процесс (ключ не покидает main), цикл tool-calling до 25
шагов, ~40 инструментов (чтение проекта, узлы, связи, варианты, эффекты, персонажи,
локации, переменные, главы, автораскладка, экспорт, сохранение, `bulk_apply` с
временными id), одна транзакция undo на сообщение, подтверждение удалений,
история чата на диске.

**Озвучка** — вкладка «Озвучка» в правой панели синтезирует голос прямо в
редакторе: у каждого персонажа свой характер и настройки (высота, темп, длительность
слога, «каждая N-я буква», разброс, дрожание, источник — два осциллятора или
загруженный WAV-сэмпл), голос проекта наследуется персонажами. Кнопка «Озвучить» в
инспекторе и прослушивание в панели, экспорт реплики или сразу всех реплик в WAV
(48 кГц, 16 бит, стерео). Движок портирован из проекта **Dialogue Voice Studio**
(плагин VST3 для FL Studio, AGPL-3.0) на чистый JS: 10 форм волны, семиполосный EQ,
биткрашер, сатурация, wavefolder, кольцевая модуляция, тремоло, компрессор, delay,
Freeverb-реверб и панорама; тайминги реплики повторяют оригинал — паузы на точках,
запятых и многоточиях, разброс высоты и громкости на каждый импульс, детерминизм по
seed.

**Студия голоса** — полный интерфейс плагина, перенесённый в StoryForge:
отдельное окно (`Ctrl+Shift+O`, меню «Вид → Студия голоса» или кнопка «Студия голоса»
во вкладке «Озвучка»). Внутри — пять вкладок как в оригинале: «Голос» (источник,
два осциллятора с расширенными формами, огибающая, глиссандо, вибрато), «Сэмпл»
(волна с обрезкой мышью и зумом колесом, затухания, реверс, нормализация),
«EQ» (семиполосный эквалайзер с перетаскиваемыми точками и живым спектром),
«Эффекты» (фильтр, биткрашер, сатурация, wavefolder, кольцевая модуляция, тремоло,
компрессор, delay, реверб, панорама) и «Диалог» (поле реплики до 600 символов,
частота/каналы/глубина, кнопки «WAV · импульс», «WAV · реплика», «8 вариаций»).
Сверху — ASCII-портрет с полосой уровня и прогрессивным показом текста, пять кнопок
действий («Один звук», «Озвучить реплику», «Стоп», «Повторить дубль», «Новый дубль»),
сохранение и загрузка голоса в `.dvoice`, компактный режим, drag&drop WAV.

**Обзор сюжета** открывается во вкладке через меню «Вид → Обзор сюжета», кнопку
«Обзор» или `Ctrl+Shift+G`. Каждый кружок представляет запись проекта. По цвету
можно различить типы записей, по размеру — число связей. Прямые серые линии
показывают переходы, авторство реплик, привязку к главам и локациям, чтение
и запись переменных.

Наведите курсор на кружок, чтобы увидеть название и его ближайших соседей.
Связанные с ним линии плавно становятся фиолетовыми, остальной граф приглушается.
Потяните кружок в сторону и отпустите — связи потянут его и соседей к новому
равновесию. Щелчок открывает запись, перетаскивание фона сдвигает обзор,
колесо меняет масштаб вокруг курсора. Кнопка с волшебной палочкой пересобирает
раскладку. Шестерёнка открывает поиск, фильтры, группы по главам, легенду,
настройки подписей и сил. Клавиша `F` вписывает граф в окно.

**Хоткеи** — `Ctrl+S` сохранить, `Ctrl+Shift+S` сохранить как, `Ctrl+O` открыть,
`Ctrl+N` новый, `Ctrl+Z`/`Ctrl+Shift+Z`/`Ctrl+Y` отмена/повтор, `Ctrl+F` поиск,
`Ctrl+K` быстрый переход, `Ctrl+D` дублировать узел, `Ctrl+G` автораскладка,
`Ctrl+Enter` новый узел после текущего, `Ctrl+Shift+V` вкладка «Озвучка»,
`Ctrl+Shift+O` студия голоса, `Ctrl+Shift+G` обзор сюжета, `Ctrl+V` вставить изображение в выбранный узел, `Delete`
удалить, `F5` валидация, `Ctrl+1..5` вкладки левой панели, `Ctrl+Shift+A` панель AI,
`Esc` закрыть.

## Производительность

Проект на 200–500 узлов остаётся отзывчивым: правка в поле стоит около 1 мс,
набор текста не порождает длинных задач, панорамирование и зум идут на 60 fps.
Что для этого сделано:

- **Граф обновляется точечно.** `graph.refresh()` сравнивает подписи карточек и
  переписывает только изменившиеся (`patchGraph`), двигает `transform` у сдвинутых
  узлов и перерисовывает рёбра лишь при смене связей или высот карточек. Полная
  пересборка `svg.innerHTML` (около 50 мс на 200 карточках) осталась только для
  смены фильтра, набора и загрузки проекта.
- **Текст в SVG отсекается по экрану.** Текстовые узлы — самая дорогая часть
  лэйаута (около 0.03 мс каждый; 1239 надписей давали 40 мс на каждый кадр).
  Карточки за пределами кадра получают класс `is-far`, при зуме ниже `0.55` —
  класс `is-small` на самом `svg`; в обоих случаях CSS скрывает текст через
  `display: none`. Пересчёт видимого слоя стоит около 0.7 мс и делается из
  координат модели, без чтения геометрии из DOM.
- **Инспектор не пересобирается при вводе.** Правки текста, заголовка, эмоции,
  спикера, локации, тегов, вариантов и эффектов идут «тихо»
  (`apply(..., { refresh: false })`): обновляется только счётчик слов, а полная
  перерисовка панели остаётся для смены выделения и действий, меняющих состав
  списков (добавить/удалить/переставить).
- **Высоту текстового поля считает CSS** (`field-sizing: content`), а не JS через
  чтение `scrollHeight` — это убирало принудительный лэйаут примерно на 38 мс
  после каждой перерисовки панели.

Замеры предыдущего выпуска на графе из 201 узла: нажатие клавиши —
1.3 мс (было 38.7), набор 20 символов — 23 мс работы и ни одной длинной задачи
(было 16 задач по 50–60 мс), пан/зум — средний кадр 6 мс, p95 8 мс, автораскладка
201 узла — 126 мс, `store.apply` одной правки — 2.8 мс, валидация — 3.3 мс,
автосохранение (сериализация 169 КБ) — 1.4 мс. Скрипты замеров лежат в
`tools/_probe-perf*.mjs` (см. `tools/README.md`).

## Из текста в ноды

Откройте вкладку **Сценарий** и напишите сцену обычным текстом. Укажите, где она происходит, кто говорит и что меняет выбор игрока. Текст сохраняется внутри проекта. Нажмите **Создать ноды…**, проверьте сообщение в чате и отправьте. Ассистент может также править выбранный фрагмент, продолжать существующие ветви и переиспользовать персонажей. **Ctrl+Z** отменяет правки одного запроса вместе.

В настройках AI укажите ключ и точный ID модели. По умолчанию выбран один DeepSeek. Для шлюза с несколькими моделями выберите свой сервер, введите его OpenAI-совместимый адрес и основную модель. Включите **Режим агентов** и перечислите **Модели-соавторы** по одной на строку. После вертикальной черты можно указать задачу, например «диалоги». Соавторы получают текст проекта и текущие вложения параллельно через одно подключение. Основная модель сверяет варианты и вносит итоговые правки. Черновик и статус каждого участника видны в чате.

Фото можно вставить из буфера, перетащить или прикрепить кнопкой в чате. Для официального API DeepSeek поддержка изображений есть у модели `deepseek-flash`. [Фото в API DeepSeek](https://api-docs.deepseek.com/guides/vision/)

В настройках AI можно раскрыть **Встроенные навыки сценариста**. Три встроенных навыка помогают писать диалоги, выстраивать сцены и редактировать черновик. Их источники и условия использования доступны в установленном приложении. [Исходная коллекция навыков](https://github.com/jwynia/agent-skills)

## Перенос проекта и голосов

Сохраните историю в формате `.sfproj` через **Ctrl+S**. В этом файле хранятся узлы, переходы, персонажи, изображения и настройки озвучки, включая загруженные WAV. Для переноса скопируйте файл на другой компьютер и откройте через **Ctrl+O**. Реплика использует собственный голос, если он задан, затем голос персонажа, затем голос проекта. Библиотека студии хранит на этом компьютере именованные голоса для повторного использования.

## Структура

```
storyforge/
  main.js              главный процесс: окна, меню, fs, AI-прокси, автосейв, логи
  preload.js           contextBridge: window.sf (единственный мост в рендерер)
  src/index.html       каркас интерфейса
  src/styles.css       дизайн-система (переменные, тёмная/светлая темы)
  src/js/model.js      модель .sfproj, операции, Store с undo/redo, валидация, статистика
  src/js/graph.js      SVG-граф: карточки, рёбра, пан/зум/драг, контекстное меню
  src/js/inspector.js  правая панель: поля узлов и сущностей
  src/js/panels.js     левая панель: 6 вкладок + оверлей валидации
  src/js/export.js     экспорт: Godot / Ren'Py / Markdown / JSON
  src/js/ai.js         AI-ассистент: инструменты, tool-цикл, чат
  src/js/voice.js      вкладка «Озвучка»: пресеты, параметры, прослушивание, экспорт WAV
  src/js/voice-studio.js  студия голоса: пять вкладок, волна, EQ, экспорт как в плагине
  src/js/media.js      изображения: импорт, сжатие в WebP, буфер обмена, drag&drop
  src/js/visualizer.js обзор сюжета: canvas-граф со связями и force-directed физикой
  src/js/voice/        движок озвучки (порт Dialogue Voice Studio):
    dsp.js             шум, биквады, 10 форм волны, Freeverb
    params.js          параметры с подписями, 4 характера голоса, диффы от пресета
    render.js          синтез реплики: тайминги, паузы, разброс, эффекты
    wav.js             кодирование/декодирование WAV (8–32 бит, 8–384 кГц)
  src/js/app.js        bootstrap, ui-хелперы, меню, хоткеи, статусбар
  CONTRACT.md          контракт модулей (API, операции, DOM-id, коды валидации)
  tools/               проверки и приёмка (см. tools/README.md)
```

Данные приложения (настройки, автосейв, история чата) — в профиле `--user-data-dir`,
логи — в `.logs/`.

## Проверки

```powershell
node tools/verify.mjs           # 138 проверок: синтаксис, контракт, модель, экспорт, озвучка, студия, изображения, обзор, производительность
node tools/_selftest-export.mjs # экспорт на синтетическом проекте
node tools/_selftest-voice.mjs  # движок озвучки: параметры, DSP, рендер, WAV, выделение, EQ (61)
npm.cmd run selftest            # окно Electron, отдельный профиль и локальная AI-заглушка
node tools/acceptance.mjs       # сводка по 20 критериям приёмки
```

Каждый запуск `npm.cmd run selftest` создаёт временный профиль, запускает локальную
AI-заглушку на свободном порту и печатает путь к свежему `selftest.json`.
Проверки включают сообщение AI, правки модели, отмену транзакции и историю.
