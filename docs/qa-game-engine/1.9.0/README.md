# Проверка игрового ассистента StoryForge 1.9.0

**Настоящий DeepSeek.** В игровой чат вводили задания на русском языке в отдельных синтетических проектах. Использовалось подключение Zexkora, модель `standard/deepseek-v4.1-flash` и протокол Anthropic Messages. Проверка сравнивала фактические данные проекта с ожидаемыми значениями после ответа. Для заданий без правок дополнительно проверяли, что модель сохранила исходную игру. [Ответы и результаты по каждому заданию](deepseek.md) · [Данные JSON](deepseek.json).

В первом прогоне модель завершила семь из девяти заданий. Панель инвентаря и прохождение через мастерскую дошли до ограничителя тестового стенда. На девять заданий ушло 54 обращения по штатному протоколу, ещё 16 — на предварительную проверку транспорта по совместимому OpenAI-маршруту. Предварительную проверку остановили при переходе на штатный протокол, завершённых оценок по ней нет. При остановке задачи с панелью программа вернула черновик в чат и сохранила проект без частично применённых правок.

**Проигрыватель и редактор.** Отдельная серия подаёт заранее заданные команды через локальный тестовый API. Команды исполняет установленное приложение. Тест управляет героем клавиатурой, читает показанную реплику и HUD, сравнивает позиции, сохраняет файл и заново открывает его в другом процессе. [Игровые задачи и снимки экрана](gameplay.md) · [Вызовы инструментов и наблюдения](gameplay.json).

| Что обнаружили | Что изменилось | Как проверяли |
|---|---|---|
| По истории чата модель могла спутать открытую комнату со стартом героя | При каждой отправке фиксируются карта, камера, выделение и задача | Выбор второго из двух одноимённых персонажей, старт в другой точке, смена карты |
| После задержки кадра следующий шаг мог закончиться слишком быстро | После большого перерыва у следующего шага есть полная длительность | Удержание кнопки, автоповтор, редкие кадры и единичное подвисание при 90, 180 и 330 мс на клетку |
| Симулятор и команда «Играть» по-разному выбирали старт в комнате, где весь свободный пол занят событиями касания | Оба допускают резервную стартовую клетку в такой комнате | Комната из одной клетки с нажимной плитой |
| Модель тратила много обращений на путь к NPC и проверку панели | Один вызов может пройти до названного события, продолжить разговор, перейти в другую комнату и вернуть начальное и итоговое состояние панелей | Контроль игрового флага, двух комнат и обратной двери, обход стен и посторонних событий |
| В первом тесте открытия файла после перезапуска проверка продолжала читать закрытое окно | Стенд заново получает игровое окно после перезапуска | Тот же файл снова открывали в отдельном процессе и проходили событие «Старый маяк» |

В наборе автоматической регрессии приложения прошли 114 тестов. Для ошибки самого стенда также сохранены [исходный протокол](reopen-first-attempt.json) и [снимок окна](evidence/fail-reopen.png).

Чтобы воспроизвести локальные испытания, выполните команды из каталога проекта.

```shell
npm test
npm run test:rpg
npm run test:rpg-chat
npm run test:rpg-trials
```

Для проверки конкретной установленной сборки задайте `STORYFORGE_EXE` её полным путём. Игровые сценарии используют временные профили. Для проверки модели отдельный сценарий `tools/test-rpg-live.mjs` требует явного включения платного режима и настроенного подключения.
